## Wymagania

| Wymaganie | Po co |
|---|---|
| [Claude Code](https://claude.com/claude-code) **2.1.287+** | Pierwsza wersja z modami. `sdd` rejestruje narzędzie `doctor_check` jako mod. |
| **Git** | Każda funkcja żyje na własnej gałęzi. |
| [GitHub CLI](https://cli.github.com/) (`gh`), zalogowany | `/sdd:review` otwiera nim PR, gdy nie skonfigurowano akcji `pr`. |

<Aside type="caution">
W WSL oraz z `--safe-mode` mody nie działają, a `/sdd:doctor` przechodzi na sprawdzanie ręczne.
</Aside>

## Instalacja pluginu

Raz na maszynę.

<Steps>

1. Dodaj marketplace i zainstaluj:

   <Tabs>
     <TabItem label="Claude Code">
       ```text
       /plugin marketplace add JanSzewczyk/spec-driven-development
       /plugin install sdd@spec-driven-development
       ```
     </TabItem>
     <TabItem label="Shell">
       ```bash
       claude plugin marketplace add JanSzewczyk/spec-driven-development
       claude plugin install sdd@spec-driven-development
       ```
     </TabItem>
   </Tabs>

2. Włącz go w `~/.claude/settings.json`:

   ```json
   {
     "enabledPlugins": {
       "sdd@spec-driven-development": true
     }
   }
   ```

3. Zweryfikuj:

   ```bash
   claude plugin list | grep sdd
   ```

</Steps>

11 skilli, 3 agenty i narzędzie `doctor_check` są teraz dostępne w **każdym** projekcie. Nic nie jest kopiowane do projektów.

## Instalacja sdd-board (opcjonalnie)

```text
/plugin install sdd-board@spec-driven-development
/sdd-dashboard
```

Deklaruje `sdd` jako zależność, więc instalacja sdd-board instaluje też `sdd`. Zobacz [sdd-board](/spec-driven-development/pl/board/overview/).

## Fork dla organizacji

Dla własnej kopii z własnymi ustawieniami domyślnymi:

<Steps>

1. Zrób fork repozytorium i zaktualizuj `homepage` w `plugins/sdd/.claude-plugin/plugin.json`.
2. *(Opcjonalnie)* Edytuj `plugins/sdd/skills/doctor/templates/capabilities.yml.template`, aby ustawić domyślny flow implementacji.
3. *(Opcjonalnie)* Edytuj `plugins/sdd/skills/doctor/templates/constitution.md.template`, aby dodać standardowe reguły WHAT NOT TO DO.
4. Podbij `version` w `plugin.json` i we wpisie `sdd` w `.claude-plugin/marketplace.json`. Po merge do `main` workflow wydania taguje `v<version>` i tworzy GitHub Release.
5. Użytkownicy dodają Twój fork przez `/plugin marketplace add <your-org>/<your-repo>` i instalują `sdd@spec-driven-development`.

</Steps>
