import { Card, CardGrid } from '@astrojs/starlight/components';

## Write it down

<CardGrid>
  <Card title="Make work verifiable">
    Every task's `acceptance` points to measurable criteria; `/sdd:review` verifies against them. Default to test-first in your implementation flow.
  </Card>
  <Card title="The constitution is the WHY">
    Each WHAT NOT TO DO rule carries a `**Why:**` (and an incident reference when applicable). After every Claude mistake, append the lesson. Without rationale, rules become folklore and get re-broken.
  </Card>
  <Card title="Keep spec and code in sync">
    When you change code by hand, update the spec. Run `/sdd:analyze` periodically.
  </Card>
  <Card title="A CLAUDE.md per module">
    Root for cross-cutting rules, one per app or package for the rest, each lean and pointing at `specs/constitution.md`. The framework never touches them.
  </Card>
</CardGrid>

## Review at the right moments

<CardGrid>
  <Card title="Plan Mode for /sdd:plan">
    Claude cannot modify files while exploring; approving the plan saves it. Not for `/sdd:clarify`, which writes into the spec.
  </Card>
  <Card title="Read plan.md">
    Always, before `/sdd:tasks`. The cheapest moment to correct course.
  </Card>
  <Card title="Embrace Clarify">
    Questions before planning surface gaps that would burn implementation cycles.
  </Card>
  <Card title="One branch per feature">
    `/sdd:spec` enforces it, with Conventional Commits naming.
  </Card>
</CardGrid>

## Keep sessions small and cheap

<CardGrid>
  <Card title="Shard large specs">
    Never hand a giant PRD to an implementer. Epic → Task; each implementer gets only its task's brief.
  </Card>
  <Card title="Sub-agents for large reads">
    Don't grep 50 files in the main session; receive a summary.
  </Card>
  <Card title="Fresh chat per task">
    `/clear` between phases and open a new session per task. `tasks.md` status is the handover.
  </Card>
  <Card title="Tier your models">
    Opus for judgement phases, Sonnet for mechanical ones. See [Cost](/spec-driven-development/guides/cost/).
  </Card>
  <Card title="Batch feedback">
    Collect visual and QA tweaks and NOT READY fixes into one message per round; each turn reprocesses the full context.
  </Card>
</CardGrid>
