The board is the side panel of the [sdd mod](/spec-driven-development/mod/overview/). It only **reads** `specs/` and never writes to it.

```text
/sdd-dashboard
```

At session start it opens by itself when the project has `specs/` and the window has room for it; otherwise a toast says to type `/sdd-dashboard`. A board you close stays closed until you run `/sdd-dashboard`. To open it only by hand, turn off the `show_board` option. Try it without installing: `claude --plugin-dir plugins/sdd`.

## What it shows

- **Session strip:** on the spec's branch the board names the **main SDD session**; on a task branch (`<spec-branch>--<EPIC>-T<n>`) it names the **task session** and says the statuses come from the spec branch's checkout.
- **Live strip** (top of Current): what runs now in this session. The `/sdd:*` command of the turn with its time, the latest tool call, and one lane per subagent (from `agent.spawn` to its end, with its last tool calls), per task running in its worktree (with the last commit of its branch) and per task PR waiting for a merge. Subagent lanes sit on a 15-minute time axis. Each lane expands to show where it was read from. With nothing running it is one line.
- **Current:** the active spec (from the git branch, one you pinned, or the newest in progress): title and status, a **phase bar** (Spec → Clarify → Plan → Tasks → Implement → Review, the current phase wider and animated; when `/sdd:clarify`, `/sdd:plan` or `/sdd:tasks` waits for your reply between turns, the phase stays marked without the animation), a phase card with task progress, the readiness checklist and the next `/sdd:*` command with a **Run** button (sent as if you typed it, queued until the session is idle), **Implement all** while more than one task is open (`/sdd:implement` with no argument: every open task in turn) and **Put in prompt** (or "running now" while it runs), the task flow (waves of tasks that can run side by side, drawn from `depends_on`, once a task depends on another), the task list (filter All / Open / Blocked; a row expands to its acceptance ids, dependencies, branch and PR; hovering a task lights its lane), and buttons that open `spec`, `plan`, `tasks`, `review`.
- **Review card** (in the Review phase, instead of the phase card): every check `/sdd:review` runs, taken from `review:` in `capabilities.yml` and grouped by step: tests per project, `spec-verifier`, each `review.checks` entry and each `agent:` audit (in parallel), then the reviewer's constitution rules and skill audits, then commit and PR. A bar has one segment per check. While the review runs, each row follows its agent (the live strip leaves those agents to the card); afterwards it shows the result from `review.md` (PASS / FAIL, counts, findings with `file:line`), the verdict, the blockers split into must fix and can be accepted (each with its task), the accepted ones, and how old `review.md` is. A must-fix blocker that names a task makes `/sdd:implement <task>` the next step.
- **Ticket** (task sessions only, opened first): the task's scope, acceptance criteria with their text from `spec.md`, dependencies, branch, PR and files. The spec stays one tab away.
- **All:** every spec with a small phase bar and task progress, filterable. **Show** pins one as current.
- **Config:** read-only, in its own pane. Projects, effective `capabilities.yml` values (set vs default), per-project commands from constitution §2, plus buttons for `/sdd:capabilities` and `/sdd:doctor check`.
- **+ New spec:** puts `/sdd:spec feat ` in the prompt. Shown only on a branch with no spec, so a spec session has no button to start another.

- **No SDD in the project:** only a setup card. **Init SDD in this project** runs `/sdd:doctor init`; it is the only button that runs a command, all others just fill the prompt.
- **Live:** refreshes after Claude or a sub-agent writes under `specs/`, after a branch switch, merge, pull or `gh pr` command, after each turn, and every 4 s for edits made elsewhere. While shown it asks GitHub about task PRs at most once a minute and checks task branches fast-forwarded into the SDD branch, so a merged task shows as merged before Reconcile records it. In a task worktree it reads the statuses from the SDD branch's checkout. A footer line says when the data was last read.
- **Rendering:** SVG in Desktop and VS Code (animation only inside drawings, off with reduced motion), text in the terminal.

## How it picks the next step

| On disk | Next |
|---|---|
| spec `draft` | `/sdd:clarify` |
| spec `clarified` | `/sdd:plan` |
| spec `planned`, no `tasks.md` | `/sdd:tasks` |
| tasks exist, some not implemented | `/sdd:implement T<n>` for the first unfinished task whose dependencies are done and that does not run in its own worktree |
| the rest run in their task worktrees (`branch:`) or wait for task PRs (`pr:`), and unfinished tasks depend on them | `/sdd:implement`: a running one continues by itself as tasks land, else run it again |
| only task PRs (`pr:`) are left | `/sdd:review` after the merge (it marks the merged tasks `review` first) |
| every task in `review` or `done` | `/sdd:review`; after a NOT READY review whose must-fix blockers name a task, `/sdd:implement <task>` |
| spec `done` or review verdict READY | nothing, open the PR |
