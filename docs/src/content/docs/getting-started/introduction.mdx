Vibe coding (loose prompt, AI guesses, iterate by trial and error) works for demos and breaks in production: every fix breaks something else, security gaps multiply, the codebase turns unmaintainable.

**SDD inverts it.** The specification is the source of truth; code is its mechanical consequence. Claude reads and confirms a plan before a single line is written, and a final review checks the result against the acceptance criteria before anything is committed.

## Vibe coding vs SDD

| | Vibe coding | SDD |
|---|---|---|
| **Starting point** | A vague prompt | A reviewed spec with acceptance criteria |
| **Design** | Implicit, in the model's head | `plan.md`, approved by you in Plan Mode |
| **Work units** | One long chat | Self-contained tasks, one per session |
| **Done means** | "Looks right" | Every acceptance criterion verified |
| **Lessons** | Forgotten | Written into the constitution |

## What the framework does and does not do

| | |
|---|---|
| **Manages** | Research, spec, plan, self-contained tasks, the hand-off, and the final audit. |
| **Leaves to you** | The implementation itself. Point `/sdd:implement` at the skill, agent or command you already use. |

## What is in the box

| Piece | What | Role |
|---|---|---|
| **11 skills** | Slash commands, started only by you | `doctor`, `constitution`, `spec`, `clarify`, `plan`, `tasks`, `implement`, `review`, `retro`, `analyze`, `capabilities` |
| **3 agents** | Sub-agents, invoked by commands | [`spec-verifier`](/spec-driven-development/agents/overview/#spec-verifier), [`reviewer`](/spec-driven-development/agents/overview/#reviewer), [`codebase-surveyor`](/spec-driven-development/agents/overview/#codebase-surveyor) |
| **1 mod** | Registers the `doctor_check` tool | Powers `/sdd:doctor check` |
| **sdd-board** | Optional Desktop panel | [Shows where each spec stands](/spec-driven-development/board/overview/) |
