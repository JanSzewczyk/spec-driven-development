# `specs/capabilities.md` values

Read this when a step reads `## Implementation`, `## Actions` or `## Review`.

`## Projects` is auto-generated by `/sdd:doctor init`; the other sections belong to the user.
A missing section or line means the default below.

## Who does a step

`skill:<name>` · `agent:<name>` · `command:<shell>` · `in-session`

| Value | Hand-over |
|---|---|
| `skill:<name>` | invoke it with the Skill tool, the input as the argument |
| `agent:<name>` | Agent tool with that `subagent_type`, the input as the prompt |
| `command:<shell>` | run it with Bash, the input on stdin |
| `in-session` | the session does it itself |

## Sections

| Section | Keys | Default |
|---|---|---|
| `## Implementation` | `default`, one line per project (`<project>: <value>`) — who implements a task; the project's line wins over `default` | `default: in-session` |
| `## Actions` | `branch`, `commit`, `pr` — `skill:` / `agent:` / `command:` | unset: the session uses git and `gh` (or a matching skill it has) |
| `## Review` | `tests: run\|skip` · `publish: ask\|off` · `default: auto\|skill:<name>\|agent:<name>` and one line per project for the audit flow · `checks:` extra `agent:` / `skill:` entries run on every review | `tests: run`, `publish: ask`, `default: auto`, no checks |
| `## Generated / out-of-band paths` | one glob per line | none |

Unknown keys (for example `ui:` from older versions) are ignored.

A `checks:` entry that is an agent returns `PASS | FAIL | SKIPPED` with findings. `FAIL` blocks
READY, `SKIPPED` never does.
